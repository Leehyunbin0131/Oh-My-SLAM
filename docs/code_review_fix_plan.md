# 주행·지도 콘솔 통합 수정 계획

이 계획의 기준은 `72d3860`이며 구현 결과와 조건별 검증 범위는 [수정 검증 결과](code_review_fix_results.md)에 정리했다. **주행에서 먼저 수정할 문제는 DWB의 반대 회전이다.** 사용자가 기록한 두 실패 주행을 재생했을 때 설치된 제어기가 84개 시점 모두 같은 명령을 골랐다. 첫 시점에서 전역 경로는 시계 방향으로 약 117° 돌도록 했지만, DWB는 반시계 방향 0.01579 rad/s를 골랐다. 경로 중간의 방향을 반전해도 후보 점수는 그대로였다.

같은 우선순위로 **고속 취소 후 제동거리, 차체 안쪽 장애물 누락, 저장 지도에서 금지 구역이 사라지는 문제**를 다룬다. 각각 독립적으로 재현한 문제여서 한 수정이 끝나야 다음 수정을 시작할 필요는 없다. 아래 단계는 수정 결과를 어떤 순서로 확인할지 나타낸다.

## 3. 명령 경계와 외부 리뷰의 추가 재현

외부 리뷰가 단독 재현한 시계·명령·모드 전환 사례는 해당 모듈의 시험으로 옮긴다. 수동 입력을 놓은 뒤 전진하거나 취소한 목표가 출발할 가능성은 1단계와 함께 먼저 확인하고, 재현되면 즉시 같은 우선순위로 수정한다. 실물에서의 발생 빈도는 측정 전까지 미확인이다.

| --- | --- | --- |
| 리뷰 1·2·9·27 | 시계보다 소폭 앞서 도착하는 정지 표본·하트비트·수동/자동 명령·sim_base 오도메트리·비용지도 표본의 보류와 폐기를 정한다. 하위 CommandGate가 유효한 원본을 제한된 이력으로 대조하게 한다. 단일 슬롯 누락, +1 ms의 정지 판정 리셋과 하트비트 거절은 외부 리뷰가 직접 재현했다. | T2 원본 뒤 T1 최종 명령이 도착해도 아직 유효하고 후속 출력을 역전시키지 않는 경우에만 전달한다. 원본 300 ms 만료, 정지·취소 경계, 이전 소유자·세션, 큰 미래 시각과 시계 역행에는 과거 명령이 되살아나지 않아야 한다. ## 검증 도구와 완료 판정

아래 세 오판은 기존 기록으로 고칠 수 있다. 관련 주행의 최종 합격을 판정하기 전에 적용한다.

| 근거 | 수정할 동작 | 완료 기준 |
| --- | --- | --- |
| 조사 14–16 | 검증기에서 계획 재시도 오류를 목표·재시도와 연결한다. 취소 전 발행돼 늦게 수신한 명령과 취소 후 생성된 명령을 구분한다. 센서 차단 시간은 실제 마지막 유효 프레임에서 계산한다. | 보관 기록에서 액션 종료보다 20 ms 늦게 수신한 계획 오류, 취소 전 명령의 지연 수신, 깊이 프레임 한 장의 추가 수신을 각각 올바르게 판정한다. 취소 뒤 실제 비영 구동 출력이나 센서 정지 지연을 주입한 대조 사례는 실패해야 한다. [통합 검증기](../tools/verify_sim_navigation.py) |

1. **설치본 재생**에서 각 문제의 실패 입력과 통과 대조군을 함께 사용한다. 확인된 반대 회전 때문에 모든 RPM에서 도착 진동이 생긴다고 추론하지 않는다. Jazzy의 기본 `rclpy.spin_once`는 전역 executor를 재사용하므로 리뷰 31의 ‘콜백마다 executor 생성’ 설명은 제외하고 노드 등록·해제와 실제 기록 부하를 측정한다.
2. **Gazebo와 GUI**에서 영향을 받은 시나리오를 묶어 검증한다. P4의 기존 5개 연속 목표 인수 기록은 기준선으로 보존하고 고속 취소·장애물·지도 교체는 각각의 수정 확인에 사용한다. 직전 조사에서 미관측 목표로 중단된 후속 동적 장애물·기억 제거·루프 폐쇄는 해당 단계에 도달한 실행에서만 판정한다.
3. **실물**의 급정지 빈도, 제동거리, IMU 장착 자세에는 별도 실측이 필요하다. 시뮬레이션의 정지거리를 실물 제한으로 옮기거나 리뷰가 제안한 시계 허용치·정지 박스 축소·장애물 삭제 규칙을 측정 없이 기본값으로 적용하지 않는다. 실물 구동은 별도 운용 시험 범위다.
