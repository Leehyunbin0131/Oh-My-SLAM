# 지도 중심 로봇 콘솔

[README](../README.md) · [통합 설계](architecture.md) · [시뮬레이션 자율주행](sim_navigation.md)

**지도에서 목적지를 지정하고 실제 ROS 센서·구동 수치를 확인합니다. 별도 화면은 시스템 로그 하나입니다.** 목적지 이동과 직접 조종에 필요한 제어권 획득·모드 전환은 내부에서 처리합니다.

## 설치와 실행

ROS 2 Jazzy 환경에서 패키지를 빌드하고 Qt 환경을 준비합니다.

```bash
cd ~/MyRos/Oh-My-SLAM
source /opt/ros/jazzy/setup.bash
colcon build --base-paths src --packages-up-to omslam_operator_support \
  --cmake-args -DCMAKE_BUILD_TYPE=Release -DPython3_EXECUTABLE=/usr/bin/python3
python3 -m venv --system-site-packages .venv-operator
.venv-operator/bin/python -m pip install -r requirements-operator.txt
```

시뮬레이션·SLAM·Nav2와 콘솔을 함께 시작합니다.

```bash
./console.sh --start-sim
```

`--world airport`는 공항 지도를 사용하고, `--gazebo-gui`는 Gazebo 화면도 엽니다. 콘솔이 시작한 프로세스는 콘솔을 닫을 때 함께 종료합니다.

이미 실행 중인 ROS에 연결하려면 같은 domain에서 실행합니다.

```bash
ROS_DOMAIN_ID=11 ./console.sh
```

기본 domain은 현재 `ROS_DOMAIN_ID`를 따르고, 설정하지 않았으면 86입니다. `OMSLAM_CONSOLE_DOMAIN_ID`로 별도 지정할 수 있습니다. 외부 세션에 연결한 콘솔은 외부 Gazebo·Nav2를 종료하지 않습니다. 실물 관측은 `./console.sh --real`로 연결하며 구동·지도 변경을 허용하지 않습니다.

기본 크기는 1440×900, 최소 크기는 1280×800입니다. `--width 1280 --height 800`으로 작은 창을 열 수 있습니다. `--page 1`은 시스템 로그를 엽니다.

## 경로 디버깅 기록

목표에 접근할 때 글로벌 경로와 실제 이동이 달라지는 현상은 **`--debug-path`** 옵션으로 기록합니다. 시뮬레이션과 콘솔을 함께 시작하는 경우:

```bash
./console.sh --start-sim --debug-path
```

기존 ROS 세션에 연결할 때는 같은 domain에서 실행합니다. 월드 등 기존 실행 옵션도 함께 사용할 수 있습니다.

```bash
ROS_DOMAIN_ID=86 ./console.sh --debug-path
```

상단에 **경로 기록 중**이 표시되면 평소처럼 목표를 지정하고 **이동**을 누릅니다. 출발 전부터 접근·도착·취소까지 자동 저장하므로 별도 저장 버튼은 필요하지 않습니다. 현상을 재현한 뒤 콘솔을 정상 종료하면 남은 기록과 요약을 저장합니다. 기록 상태에 마우스를 올리면 저장 경로를 확인할 수 있습니다. **경로 기록 대기/오류**는 정상 기록 중인 상태가 아닙니다.

저장 위치는 `reports/operator/<실행 시각>/path-debug/`이며 실행마다 새 폴더를 만듭니다. 해당 폴더 전체를 보존하면 분석에 사용할 수 있습니다. `--debug-path` 없이 실행하면 경로 기록기를 시작하지 않습니다. 이미 콘솔 지원 세션이 있는 domain에서 추가 창을 열어 기록해도 기존 시뮬레이션·주행 프로세스는 새 창이 종료하지 않습니다.

- `records.jsonl`: 수신 시각·ROS 시각·원본 메시지, 목표와 경로 변화의 전체 기록
- `summary.json`: 정상 종료 여부, 기록 수·누락 수, 수신하지 못한 토픽, 최근 목표 결과
- `metadata.json`: 실행 환경, 설치 경로, 설정 파일 해시
- `grid-*.bin.zlib`: 압축된 지도·비용지도 셀. 좌표·해상도·파일 참조는 JSONL에 기록

로봇 위치와 지역 경로는 최대 10 Hz, 지도·비용지도는 최대 1 Hz로 기록합니다. 의도적인 표본 제한은 요약에 구분해 남깁니다. 기록 한도는 실행당 2 GiB이며, 한도 초과나 저장 실패는 **경로 기록 오류**로 표시합니다.

기록에는 원본·평활화된 글로벌 경로, 제어기가 받은 경로와 지역 경로, 지도 기준 로봇 위치·TF·odometry, 단계별 속도 명령, 목표 위치·도착 방향, 요청 식별자·수락·도착 결과, 주행 상태가 포함됩니다. 사용 가능한 지도·비용지도와 설정도 함께 보관합니다. 제공되지 않는 토픽은 수신하지 못한 것으로 남으며 만들어 채우지 않습니다. 서로 다른 좌표계와 시각을 함께 보존하므로 원형 글로벌 계획과 실제 짧은 접근을 비교할 수 있습니다.

기록기는 GUI와 별도 프로세스에서 관측만 수행합니다. 기록을 켜도 계획기·도착 허용오차·주행 명령은 변경하지 않습니다. 기록 파일은 로컬 `reports/`에 저장되며 Git 추적 대상에서 제외됩니다.

설치본 회귀와 격리된 모의 ROS·실제 Qt 통합 시험으로 자동 저장·목표 연결·정상 종료를 검증했습니다. 이 시험은 기록 기능의 검증이며 실제 경로 이탈의 원인 분석을 대신하지 않습니다.

## 목적지와 이동

1. 목적지 목록의 **+** 버튼을 누르고 지도에서 위치를 클릭합니다. 누른 채 드래그하면 도착 방향도 정합니다.
2. 여러 곳에 가려면 같은 방법으로 목적지를 더합니다. 지정 중에는 **취소**로 바뀐 `+` 버튼, 지도 안내의 **취소**, **Esc** 또는 지도 **우클릭**으로 입력을 취소할 수 있습니다.
3. **이동**을 누릅니다. 목적지가 한 개든 여러 개든 같은 목록과 버튼을 사용합니다.

각 행의 **−** 버튼은 해당 목적지를 삭제합니다. 행 왼쪽 손잡이를 위아래로 끌면 순서가 바뀝니다. 손잡이에 키보드 초점을 두고 위/아래 방향키를 눌러도 순서를 바꿀 수 있습니다. 지도 번호와 연결선은 목록 순서를 따릅니다.

지도 마커를 끌어 위치를 옮기고 방향 화살표를 끌어 도착 방향을 바꿉니다. 목록의 좌표를 누르면 숫자 입력창이 열립니다. 위치는 지도 좌표계의 m, 화면의 방향은 °입니다.

**이동**은 제어권을 얻고 AUTO 전환을 확인한 뒤 Nav2에 목적지를 전달합니다. 각 목표의 성공과 측정 정지를 확인한 다음 목표로 넘어갑니다. 실패·취소·연결 단절 시 다음 목표를 시작하지 않습니다. 이동 중에는 목록 편집을 잠급니다. 변경하려면 **정지**를 누르고 정지가 확인된 뒤 편집합니다.

속도는 **바퀴별 RPM 상한**으로 지정합니다. 막대는 0.1 RPM 간격이며 옆 숫자칸에는 허용 범위 안의 소수값을 직접 입력하고 Enter 또는 초점 이동으로 적용합니다. 시뮬레이션 범위는 **3–70 RPM**, 시작값은 **35 RPM**입니다. 0 RPM은 정지 명령으로 사용하지 않으며 정지는 **정지** 버튼으로 요청합니다. 실제 제한 표시는 서버가 승인한 상태를 따릅니다. 직진·회전 조합에서도 두 바퀴를 같은 비율로 축소해 지정한 RPM 상한을 지키며, 두 바퀴 중 큰 절댓값이 최소 구동 하한(3.0 RPM) 미만인 명령은 끌어올리지 않고 0으로 차단합니다(3 RPM 선택 시에도 제자리 회전은 3 RPM 순수 회전 경계까지 허용). 실물 관측 연결은 구동 설정을 변경할 수 없습니다.

## 지도 보기와 진입 금지 구역

**로봇 따라가기**를 누르면 지도의 관측 가능한 영역 중앙에 최신 로봇 위치를 유지합니다. 확대·축소해도 따라가기를 유지하며, 지도를 드래그하거나 **전체 보기**를 누르면 해제합니다. 위치 관측이 끊기면 오래된 위치로 다시 이동하지 않습니다.

**진입 금지 → 사각형 추가**를 누른 뒤 지도에서 대각선으로 드래그합니다. 서버가 승인한 영역은 붉게 표시되고 목록에서 개별 삭제할 수 있습니다. 구역은 최대 64개, 가로·세로 최소 5 cm입니다. 그리기는 Esc·우클릭·취소 버튼으로 중단합니다.

구역을 적용하기 전에 제어권·구동 해제·측정 정지를 확인합니다. 실행 중인 경로는 먼저 정지한 뒤 편집합니다. 적용 후 자동으로 재출발하지 않습니다. 전역·지역 비용지도에 구역을 표시하여 경로와 차체 footprint를 검사하고, 직접 조종에서도 지도 위치를 확인하며 진입 방향의 명령을 차단합니다. 구역이 있을 때 지도 위치를 확인할 수 없으면 이동을 허용하지 않습니다. 이 가상 경계는 물리적인 제동거리 인증을 대신하지 않습니다.

**지도 저장**은 구역도 함께 저장합니다. **저장 지도 열기**는 선택한 지도에 묶인 구역을 복원하고 **새 지도 작성**은 빈 구역으로 시작합니다. 불러온 AMCL 지도에서 구역을 바꾼 뒤 저장하면 새 이름으로 지도와 구역을 복사하며 원본은 덮어쓰지 않습니다. 구역 변경을 보존하려면 지도를 저장해야 합니다.


## 직접 조종과 정지

패드를 누른 채 움직이거나 Space + 방향키를 사용합니다. 자율 이동 중 직접 조종을 시작하면 현재 목표를 취소하고 측정 정지를 확인한 뒤 MANUAL로 전환합니다. 전환이 끝날 때에도 입력을 계속 누르고 있어야 움직입니다.

입력을 놓거나 창의 초점을 잃으면 직접 조종 명령을 해제합니다. 창을 숨기거나 최소화할 때도 입력을 해제합니다. 상단 **정지**는 모든 화면에서 즉시 요청할 수 있으며 현재 이동과 대기 중 입력도 취소합니다. 후진은 후방 관측이 검증된 제어 서버에서만 허용됩니다.

GUI 이벤트 루프가 멈추거나 연결이 끊기면 기존 0.30초 제어권 수명에 따라 로봇 측에서 정지·권한 해제를 처리합니다. 재연결은 관측 상태에서 시작하며 이전 목표나 직접 조종을 자동 재개하지 않습니다. 다른 콘솔의 제어권은 자동으로 가져오지 않습니다.

## 화면 정보

| 위치 | 내용과 조작 |
| --- | --- |
| 상단 상태 | 이동 가능 여부와 준비되지 않은 이유: 연결, 지도, 현재 위치, 경로, 제어 차단 |
| 지도 | 실제 점유 지도·로봇 위치·계획 경로·목적지·라이다·장애물 기억·costmap 레이어 |
| 상단 계측 | 선속도·각속도·로봇 위치 |
| 오른쪽 영상 | RGB·깊이 영상. 한 번 눌러 확대 |
| 하단 반투명 표시 | 좌우 RPM, 롤·피치·지도 기준 방향, host/로봇 CPU·메모리·CPU 온도 |
| 지도 도구 | 저장·불러오기·새 지도·현재 위치 맞추기와 레이어 선택 |
| 시스템 로그 | 조작 기록과 엔코더·PWM·통신·IMU·카메라·인지 세부 정보 검색 |

라이다는 각 스캔의 측정 시각에 맞는 TF로 지도에 표시합니다. TF가 잠깐 늦으면 직전의 유효한 점군을 유지하고 변환을 재시도합니다. 원래 수신 시각 또는 측정 시각에서 0.30초가 지나면 점군을 지워 수신 단절을 가리지 않으며, 시뮬레이션 시각이 초기화되면 이전 점군도 비웁니다. 시스템 로그의 라이다 상세 정보에서 `display_status`, `display_stamp`, `tf_error`를 확인할 수 있습니다.

카메라 기반 장애물 기억·장애물 점군과 원시 깊이 점군에도 같은 TF 대기·만료 규칙을 적용합니다. 새 빈 점군을 받으면 이전 표시를 즉시 지우며, 뒤늦은 TF나 오래된 메시지로 과거 점군을 되살리지 않습니다. 카메라 상세 로그의 `cloud_info`에 각 점군의 표시 상태와 TF 오류가 기록됩니다.

하단은 124px 높이로 핵심 숫자만 표시합니다. 그래프·배터리·모터 온도와 기술 정보 팝업은 표시하지 않습니다. 수신하지 못했거나 오래된 수치는 `—`로 표시합니다. 시뮬레이션이 제공하지 않는 MCU raw·PWM 값이나 로봇 호스트 진단값을 만들어 표시하지 않습니다.

지도 방향은 지도 좌표계의 로봇 자세에서 계산합니다. 카메라는 실제 이미지 토픽을 사용하며 아직 없거나 오래된 영상에는 상태를 표시합니다. 로그는 실제 ROS 데이터·진단과 조작 결과를 표시하며 검색해 확인할 수 있습니다. 긴 내용은 세 줄로 접어 표시하고 해당 행을 누르면 전체 내용을 펼칩니다.

## 지도 작업

- **저장**: 저장할 절대 경로의 이름을 입력합니다. 확장자를 뺀 경로를 기준으로 지도 이미지·YAML·메타데이터·금지 구역을 저장하며 기존 파일을 덮어쓰지 않습니다.
  온라인 SLAM에서는 그래프도 저장합니다. 불러온 AMCL 지도를 다른 이름으로 저장할 때는 새 SLAM 그래프가 생성되지 않습니다.
- **불러오기**: 저장된 지도 YAML 경로를 입력합니다. 현재 이동을 정지하고 AMCL 위치추정으로 전환합니다.
- **현재 위치**: 지도에서 실제 로봇 위치와 방향을 지정해 AMCL 초기 위치를 보냅니다. 위치추정 준비가 끝나야 이동할 수 있습니다.
- **새 지도**: 현재 이동을 정지하고 온라인 SLAM으로 전환합니다.

불러오기·새 지도 전환은 콘솔이 시작한 Nav2 세션에서 지원합니다. 외부 세션에서는 해당 프로세스를 재시작하지 않으며 로그와 안내 문구에 불가 사유를 표시합니다. 파일 경로는 지도 서비스를 실행하는 호스트 기준입니다.

## 실행 구조와 기록

`console.sh`는 workspace 설치본을 실행합니다. `omslam_operator`는 Qt 이벤트 루프와 ROS worker를 분리하고 기존 `/operator/control`, `/operator/manual`, `/operator/navigate`, `/operator/stop`, `/operator/speed_limit`, `/operator/maps`, `/operator/set_keepouts`, `/operator/keepouts` 계약을 사용합니다. GUI는 최종 `/cmd_vel`에 직접 발행하지 않습니다.

화면 캡처와 표시 데이터 기록:

```bash
./console.sh --screenshot reports/operator/live-map.png \
  --snapshot reports/operator/live-map.json --screenshot-delay 5 --quit-after 6
```

인지 상태는 C++ 인지 노드의 `/perception/memory_status`를 받으며, 지도 표시에는 레이어당 최대 1,500점의 `/perception/memory_preview`를 사용합니다. costmap의 전체 장애물 정보는 `/perception/memory`에 그대로 남습니다. 센서 수신은 최신 메시지 한 개를 유지하고, `/clock`보다 먼저 도착한 메시지는 원래 수신 시각을 보존하며 시계가 따라올 때 반영합니다.

지도·전역 비용지도·지역 비용지도는 최신 원본 격자와 좌표 정보를 보관합니다. 화면에서 켠 레이어만 색상 이미지로 한 번 변환하고, 같은 원본을 다시 그릴 때는 이미지를 재사용합니다. 숨긴 레이어도 최신 원본을 수신하므로 다시 켜면 최신 격자가 표시됩니다. 목표 위치의 미관측·점유 판정에는 표시 이미지가 아닌 원본 격자를 사용합니다.

지도, RGB, 깊이, 제어 상태, 계측값, 시스템 자원, 목표 목록, 로그는 각각 변경된 데이터만 화면에 알립니다. 숨긴 지도 레이어의 수신이나 카메라 갱신은 지도 다시 그리기를 요청하지 않습니다. 화면의 데이터 수명 판정은 100ms 간격으로 계속 수행하고, 사용자 입력·제어권 heartbeat의 50ms 타이머는 화면 처리와 별도로 유지합니다.

지도·금지 구역은 `<지도>.keepout.json`에 저장하며 지도 YAML·이미지 해시로 결합합니다. 저장이 끝나면 구역·이미지·그래프·메타데이터를 먼저 게시하고 지도 YAML을 마지막에 게시합니다. 중간 실패 후에는 같은 이름으로 다시 저장할 수 있습니다. 구형 저장 방식의 `<지도>.keepout.pending`이 남아 있거나 해시가 불일치하면 불러오기를 거부합니다. 구역 파일이 없는 기존 지도는 빈 구역으로 열 수 있습니다.

이 변경은 메시지·인지·주행·GUI 설치본을 함께 빌드하고 세션을 재시작해야 적용됩니다. 실행 로그는 `reports/operator/`에 저장합니다.

현행 콘솔 GUI를 검증하려면 작업공간 루트에서 다음 명령을 사용합니다. 일반 운용과 동일한 QML과 지도 타입을 로드합니다. 이전 진입점 `verify_operator_gui.py`도 같은 검증기를 실행합니다.

```bash
/usr/bin/python3 tools/build_operator_live.py --output reports/operator/gui-build
source install/setup.bash
.venv-operator/bin/python tools/verify_operator_live.py --output reports/operator/gui-run
```

시뮬레이션 주행 없이 설치한 콘솔 화면의 로드와 작업 스레드·관측 프로세스 종료만 확인하려면 새 출력 경로와 함께 `--qml-only`를 지정합니다.
