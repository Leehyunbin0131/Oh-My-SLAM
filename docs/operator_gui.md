# 지도 중심 로봇 콘솔

[README](../README.md) · [통합 설계](architecture.md) · [시뮬레이션 자율주행](sim_navigation.md)

지도 위에서 목적지를 지정하고 실제 ROS 센서와 구동 수치를 한 화면에서 보는 데스크톱 콘솔입니다. 별도 화면은 시스템 로그 하나만 둡니다. 목적지 이동이나 직접 조종에 필요한 제어권 획득과 모드 전환은 콘솔이 내부에서 처리합니다.

## 설치와 실행

ROS 2 Jazzy 환경에서 패키지를 빌드하고 Qt 실행용 가상환경을 만듭니다.

```bash
cd ~/MyRos/Oh-My-SLAM
source /opt/ros/jazzy/setup.bash
colcon build --base-paths src --packages-up-to omslam_operator_support \
  --cmake-args -DCMAKE_BUILD_TYPE=Release -DPython3_EXECUTABLE=/usr/bin/python3
python3 -m venv --system-site-packages .venv-operator
.venv-operator/bin/python -m pip install -r requirements-operator.txt
```

시뮬레이션, SLAM, Nav2와 콘솔을 한 번에 띄우려면 아래 명령을 실행합니다.

```bash
./console.sh --start-sim
```

`--world airport`를 붙이면 공항 월드로 열리고, `--gazebo-gui`를 붙이면 Gazebo 창도 같이 뜹니다. 콘솔이 띄운 하위 프로세스는 콘솔 창을 닫을 때 함께 정리됩니다.

이미 떠 있는 ROS 세션에 붙으려면 같은 domain으로 실행하면 됩니다.

```bash
ROS_DOMAIN_ID=11 ./console.sh
```

기본 domain은 현재 `ROS_DOMAIN_ID`를 따르고, 설정이 없으면 86을 씁니다. `OMSLAM_CONSOLE_DOMAIN_ID`로 따로 지정할 수도 있습니다. 외부 세션에 붙은 콘솔은 닫을 때 외부 Gazebo나 Nav2를 종료하지 않습니다. 실물 관측 전용으로 붙을 때는 `./console.sh --real`을 쓰며, 이 모드에서는 구동이나 지도 변경을 막습니다.

창 기본 크기는 1440×900, 최소 크기는 1280×800입니다. `--width 1280 --height 800`으로 작은 창을 열 수 있고, `--page 1`을 주면 시스템 로그 화면으로 바로 열립니다.

## 경로 디버깅 기록

목표에 다가갈 때 전역 경로와 실제 로봇 이동이 달라지는 현상을 추적할 때는 **`--debug-path`** 옵션을 켭니다. 시뮬레이션과 함께 띄우는 경우입니다.

```bash
./console.sh --start-sim --debug-path
```

이미 실행 중인 ROS 세션에 붙어 기록할 때는 같은 domain에서 실행합니다. 월드 옵션 등 기존 인수도 그대로 쓸 수 있습니다.

```bash
ROS_DOMAIN_ID=86 ./console.sh --debug-path
```

상단에 **경로 기록 중**이 뜨면 평소처럼 목표를 찍고 **이동**을 누르면 됩니다. 출발 전부터 접근, 도착, 취소까지 자동으로 저장하므로 별도 저장 버튼은 없습니다. 현상을 재현한 뒤 콘솔을 정상 종료하면 남은 기록과 요약이 저장됩니다. 상태 표시에 마우스를 올리면 저장 경로를 볼 수 있고, **경로 기록 대기/오류** 상태일 때는 정상 기록 중이 아닙니다.

기록은 `reports/operator/<실행 시각>/path-debug/`에 실행마다 새 폴더를 만들어 저장합니다. 분석할 때는 그 폴더 전체를 그대로 보관하면 됩니다. `--debug-path`를 주지 않으면 경로 기록기를 아예 띄우지 않습니다. 이미 콘솔 지원 세션이 떠 있는 domain에 새 창을 하나 더 열어 기록해도, 그 새 창을 닫을 때 기존 시뮬레이션이나 주행 프로세스를 끄지 않습니다.

- `records.jsonl`: 수신 시각, ROS 시각, 원본 메시지, 목표와 경로 변화의 전체 기록
- `summary.json`: 정상 종료 여부, 기록 수와 누락 수, 수신하지 못한 토픽, 최근 목표 결과
- `metadata.json`: 실행 환경, 설치 경로, 설정 파일 해시
- `grid-*.bin.zlib`: 압축된 지도·비용지도 셀(좌표, 해상도, 파일 참조는 JSONL에 기록)

로봇 위치와 지역 경로는 최대 10 Hz, 지도와 비용지도는 최대 1 Hz로 남깁니다. 의도적으로 표본을 줄인 부분은 요약에 따로 구분해 적습니다. 실행당 용량 한도는 2 GiB이며, 한도를 넘기거나 저장에 실패하면 **경로 기록 오류**가 뜹니다.

기록 파일에는 원본·평활화된 전역 경로, 제어기가 받은 경로와 지역 경로, 지도 기준 로봇 위치·TF·odometry, 단계별 속도 명령, 목표 위치와 도착 방향, 요청 ID·수락·도착 결과, 주행 상태가 들어갑니다. 사용 중인 지도와 비용지도, 설정도 같이 보관합니다. 들어오지 않은 토픽은 억지로 채우지 않고 수신하지 못한 것으로 남깁니다. 서로 다른 좌표계와 시각을 그대로 보존하므로 원형 전역 계획과 실제 짧은 접근 경로를 나란히 비교할 수 있습니다.

기록기는 GUI와 별도 프로세스로 돌아가며 관측만 합니다. 기록을 켠다고 계획기나 도착 허용오차, 주행 명령이 바뀌지 않습니다. 기록 파일은 로컬 `reports/`에 저장되며 Git에는 올라가지 않습니다.

설치본 회귀와 격리된 모의 ROS·실제 Qt 통합 시험으로 자동 저장, 목표 연결, 정상 종료까지 검증했습니다. 다만 이 시험은 기록 기능 자체가 잘 동작하는지 확인한 것이지 실제 경로 이탈 원인을 분석해 주는 것은 아닙니다.

## 목적지와 이동

1. 목적지 목록의 **+** 버튼을 누르고 지도에서 원하는 위치를 클릭합니다. 누른 채 드래그하면 도착 방향까지 정할 수 있습니다.
2. 여러 곳을 차례로 돌려면 같은 방법으로 목적지를 더 추가합니다. 입력 중에는 **취소**로 바뀐 `+` 버튼, 지도 안내의 **취소**, **Esc**, 지도 **우클릭**으로 취소할 수 있습니다.
3. **이동**을 누릅니다. 목적지가 한 개든 여러 개든 같은 목록과 버튼으로 움직입니다.

각 행의 **−** 버튼을 누르면 해당 목적지가 지워집니다. 행 왼쪽 손잡이를 위아래로 끌면 순서를 바꿀 수 있고, 손잡이에 키보드 포커스를 둔 채 위아래 방향키를 눌러도 순서가 바뀝니다. 지도 번호와 연결선은 목록 순서를 그대로 따릅니다.

지도 위의 마커를 끌어 위치를 옮기거나 방향 화살표를 끌어 도착 각도를 고칠 수 있습니다. 목록의 좌표를 누르면 숫자 입력창이 뜹니다. 위치 단위는 지도 좌표계 m, 화면 방향 단위는 °입니다.

**이동**을 누르면 콘솔이 제어권을 확보하고 AUTO 전환을 확인한 뒤 Nav2에 목적지를 넘깁니다. 각 목표의 성공과 측정 정지까지 확인한 뒤에야 다음 목표로 넘어갑니다. 중간에 실패하거나 취소되거나 연결이 끊기면 다음 목표는 시작하지 않습니다. 이동하는 동안에는 목록 편집이 잠기므로, 바꾸려면 먼저 **정지**를 눌러 멈춘 뒤 편집합니다.

속도는 **바퀴별 RPM 상한**으로 조절합니다. 막대는 0.1 RPM 간격이고 옆 숫자칸에 소수값을 직접 입력해 Enter를 치거나 초점을 옮기면 적용됩니다. 시뮬레이션 범위는 **3–70 RPM**, 시작값은 **35 RPM**입니다. 0 RPM은 정지용이 아니며 멈출 때는 **정지** 버튼을 누릅니다. 화면에 표시되는 제한값은 서버가 실제로 승인한 값을 따릅니다. 직진과 회전이 섞여도 두 바퀴를 같은 비율로 줄여서 상한을 지키고, 두 바퀴 중 큰 절댓값이 3.0 RPM 미만인 작은 명령은 끌어올리지 않고 0으로 끊습니다. 3 RPM으로 낮춰 놓았을 때도 제자리 회전은 3 RPM 순수 회전 경계까지 허용됩니다. 실물 관측 모드에서는 구동 설정을 바꿀 수 없습니다.

## 지도 보기와 진입 금지 구역

**로봇 따라가기**를 켜면 지도의 보이는 영역 가운데에 최신 로봇 위치를 계속 맞춥니다. 확대하거나 축소해도 따라가기가 유지되며, 지도를 직접 드래그하거나 **전체 보기**를 누르면 풀립니다. 위치 관측이 끊겼을 때는 오래된 위치로 억지로 이동하지 않습니다.

금지 구역을 추가하려면 **진입 금지 → 사각형 추가**를 누르고 지도에서 대각선으로 드래그합니다. 서버가 승인한 구역은 붉게 표시되고 목록에서 하나씩 지울 수 있습니다. 최대 64개까지 만들 수 있으며 가로·세로 최소 크기는 5 cm입니다. 그리는 도중에는 Esc, 우클릭, 취소 버튼으로 중단할 수 있습니다.

구역을 반영하기 전에 제어권, 구동 해제, 측정 정지 상태를 먼저 확인합니다. 로봇이 움직이고 있다면 먼저 정지시킨 뒤 편집해야 하며, 구역을 적용했다고 자동으로 다시 출발하지는 않습니다. 구역은 전역과 지역 비용지도에 모두 반영되어 경로와 차체 footprint를 검사하고, 직접 조종할 때도 지도 위치를 확인해 구역 쪽으로 들어가는 명령을 막습니다. 금지 구역이 설정되어 있는데 현재 지도 위치를 알 수 없는 경우에는 이동 자체를 허용하지 않습니다. 이 가상 경계는 물리적 제동거리 인증을 대신하지 않습니다.

**지도 저장**을 누르면 금지 구역도 같이 저장됩니다. **저장 지도 열기**를 누르면 그 지도에 묶인 구역을 복원하고, **새 지도 작성**을 누르면 빈 구역으로 시작합니다. 불러온 AMCL 지도에서 구역을 고친 뒤 저장하면 원본을 덮어쓰지 않고 새 이름으로 지도와 구역을 복사합니다. 구역 변경 내용을 남기려면 반드시 지도를 저장해야 합니다.

## 직접 조종과 정지

조종 패드를 누른 채 움직이거나 Space + 방향키로 직접 조종합니다. 자율주행 중에 직접 조종을 시작하면 현재 목표를 취소하고 측정 정지를 확인한 뒤 MANUAL 모드로 넘어갑니다. 전환이 끝난 시점에도 입력을 계속 누르고 있어야 움직입니다.

입력을 놓거나 창 초점을 잃거나 창을 숨기고 최소화하면 직접 조종 명령을 바로 풉니다. 상단 **정지** 버튼은 어느 화면에서나 즉시 누를 수 있고, 현재 이동과 대기 중 입력을 한꺼번에 취소합니다. 후진은 후방 관측이 검증된 제어 서버에서만 열립니다.

GUI 이벤트 루프가 멈추거나 연결이 끊겨도 기존 0.30초 제어권 수명에 따라 로봇 쪽에서 스스로 멈추고 권한을 회수합니다. 다시 연결하면 관측 상태로 시작하며, 이전 목표나 직접 조종을 자동으로 이어가지 않습니다. 다른 콘솔이 잡고 있는 제어권도 강제로 빼앗지 않습니다.

## 화면 구성

| 위치 | 보여 주는 내용과 조작 |
| --- | --- |
| 상단 상태 | 이동 가능 여부와 준비되지 않은 이유(연결, 지도, 현재 위치, 경로, 제어 차단) |
| 지도 | 실제 점유 지도, 로봇 위치, 계획 경로, 목적지, 라이다, 장애물 기억, costmap 레이어 |
| 상단 계측 | 선속도, 각속도, 로봇 위치 |
| 오른쪽 영상 | RGB와 깊이 영상(한 번 클릭해 확대) |
| 하단 반투명 표시 | 좌우 RPM, 롤·피치·지도 기준 방향, host/로봇 CPU·메모리·CPU 온도 |
| 지도 도구 | 저장, 불러오기, 새 지도, 현재 위치 맞추기, 레이어 선택 |
| 시스템 로그 | 조작 기록과 엔코더·PWM·통신·IMU·카메라·인지 세부 정보 검색 |

라이다 점군은 각 스캔의 측정 시각에 맞는 TF로 지도에 찍습니다. TF가 잠깐 늦으면 직전 유효 점군을 잠시 유지하면서 변환을 다시 시도합니다. 원래 수신 시각이나 측정 시각에서 0.30초가 지나면 점군을 지워 수신 단절을 숨기지 않고, 시뮬레이션 시각이 초기화되면 이전 점군도 바로 비웁니다. 시스템 로그의 라이다 상세 항목에서 `display_status`, `display_stamp`, `tf_error`를 확인할 수 있습니다.

카메라 기반 장애물 기억과 장애물 점군, 원시 깊이 점군에도 같은 TF 대기·만료 규칙이 들어갑니다. 빈 점군이 새로 들어오면 이전 표시를 바로 지우고, 뒤늦은 TF나 오래된 메시지로 과거 점군을 되살리지 않습니다. 카메라 상세 로그의 `cloud_info`에 각 점군의 표시 상태와 TF 오류가 남습니다.

하단 바는 124 px 높이에 핵심 숫자만 담았습니다. 그래프나 배터리, 모터 온도, 기술 정보 팝업은 넣지 않았습니다. 들어오지 않았거나 오래된 값은 `—`로 표시하며, 시뮬레이션이 제공하지 않는 MCU raw·PWM 값이나 로봇 호스트 진단값을 가짜로 채우지 않습니다.

지도 방향은 지도 좌표계의 로봇 자세로 계산합니다. 카메라는 실제 이미지 토픽을 받으며, 영상이 없거나 오래되면 그 상태를 그대로 표시합니다. 로그는 실제 ROS 데이터·진단과 조작 결과를 검색해 볼 수 있고, 긴 내용은 세 줄로 접었다가 클릭하면 펼쳐집니다.

## 지도 작업

- **저장:** 저장할 절대 경로 이름을 입력합니다. 확장자를 뺀 경로 기준으로 지도 이미지, YAML, 메타데이터, 금지 구역을 함께 저장하며 기존 파일은 덮어쓰지 않습니다. 온라인 SLAM에서는 포즈 그래프도 같이 저장합니다. 불러온 AMCL 지도를 다른 이름으로 저장할 때는 새 SLAM 그래프를 만들지 않습니다.
- **불러오기:** 저장된 지도 YAML 경로를 넣으면 현재 이동을 멈추고 AMCL 위치추정으로 전환합니다.
- **현재 위치:** 지도에서 실제 로봇 위치와 방향을 찍어 AMCL 초기 위치를 보냅니다. 위치추정 준비가 끝나야 이동할 수 있습니다.
- **새 지도:** 현재 이동을 멈추고 온라인 SLAM으로 전환합니다.

불러오기와 새 지도 전환은 콘솔이 직접 띄운 Nav2 세션에서만 지원합니다. 외부 세션에 붙은 경우에는 외부 프로세스를 재시작하지 않고 로그와 안내 문구에 이유를 표시합니다. 파일 경로는 지도 서비스가 돌고 있는 호스트 기준입니다.

## 실행 구조와 기록

`console.sh`는 워크스페이스 설치본을 실행합니다. `omslam_operator`는 Qt 이벤트 루프와 ROS worker를 분리해 두고, 기존 `/operator/control`, `/operator/manual`, `/operator/navigate`, `/operator/stop`, `/operator/speed_limit`, `/operator/maps`, `/operator/set_keepouts`, `/operator/keepouts` 계약을 통해 통신합니다. GUI가 최종 `/cmd_vel`에 직접 메시지를 쏘지는 않습니다.

화면 캡처와 표시 데이터 스냅샷은 아래처럼 뽑을 수 있습니다.

```bash
./console.sh --screenshot reports/operator/live-map.png \
  --snapshot reports/operator/live-map.json --screenshot-delay 5 --quit-after 6
```

인지 상태는 C++ 인지 노드의 `/perception/memory_status`를 받고, 지도 화면 표시에는 레이어당 최대 1,500점의 `/perception/memory_preview`를 씁니다. costmap용 전체 장애물 정보는 `/perception/memory`에 그대로 남습니다. 센서 구독은 최신 메시지 한 개만 유지하고, `/clock`보다 먼저 도착한 메시지는 원래 수신 시각을 지킨 채 시계가 따라올 때 반영합니다.

지도와 전역·지역 비용지도는 최신 원본 격자와 좌표 정보를 따로 보관합니다. 화면에 켠 레이어만 색상 이미지로 한 번 변환하고, 원본이 바뀌지 않았으면 이미지를 재사용합니다. 숨겨 둔 레이어도 백그라운드에서 최신 원본을 계속 받기 때문에 다시 켜면 최신 격자가 바로 뜹니다. 목적지 위치가 미관측인지 점유 영역인지 판정할 때는 표시 이미지가 아니라 원본 격자를 씁니다.

지도, RGB, 깊이, 제어 상태, 계측값, 시스템 자원, 목표 목록, 로그는 실제로 바뀐 항목만 화면에 알립니다. 숨겨 둔 지도 레이어가 갱신되거나 카메라 프레임이 들어왔다고 지도를 다시 그리지 않습니다. 데이터 수명 검사는 100 ms 간격으로 계속 돌고, 사용자 입력과 제어권 heartbeat용 50 ms 타이머는 화면 그리기와 분리해 유지합니다.

지도와 금지 구역은 `<지도>.keepout.json`에 저장하고 지도 YAML과 이미지 해시로 묶습니다. 저장할 때는 구역, 이미지, 그래프, 메타데이터를 먼저 내보내고 지도 YAML을 맨 마지막에 씁니다. 중간에 실패해도 같은 이름으로 다시 저장할 수 있습니다. 구형 방식의 `<지도>.keepout.pending`이 남아 있거나 해시가 안 맞으면 불러오기를 거부합니다. 구역 파일이 없는 예전 지도는 빈 구역으로 열립니다.

메시지·인지·주행·GUI 패키지를 함께 빌드하고 세션을 재시작해야 변경 내용이 반영됩니다. 실행 로그는 `reports/operator/`에 남습니다.

콘솔 GUI를 검증할 때는 워크스페이스 루트에서 아래 명령을 씁니다. 일반 실행과 똑같은 QML과 지도 타입을 불러와 확인하며, 이전 진입점 `verify_operator_gui.py`도 같은 검증기를 실행합니다.

```bash
/usr/bin/python3 tools/build_operator_live.py --output reports/operator/gui-build
source install/setup.bash
.venv-operator/bin/python tools/verify_operator_live.py --output reports/operator/gui-run
```

시뮬레이션 주행 없이 콘솔 화면 로드와 작업 스레드, 관측 프로세스 종료만 확인하고 싶으면 새 출력 경로와 함께 `--qml-only`를 붙입니다.
